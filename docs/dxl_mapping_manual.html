DXL2 초기화 매핑 설정 매뉴얼

상위(MRS)가 보내는 위치 명령 0~4095를 로보티즈 모터의 실제 엔코더 카운트로 바꾸는 규칙을 설명합니다. 설정 방법은 4가지(Case 1~4)이고, 모두 cpp_DXL_Class_v2 v0.0.8(8da94ec) 코드를 기준으로 정리했습니다.

1. 매핑이란

상위 장비는 모터 종류와 상관없이 항상 명령값 0~4095로 위치를 지시합니다. 보드는 이 명령값을 모터의 raw 카운트(Goal Position, 주소 116)로 바꿔서 보냅니다. 바꾸는 기준이 "매핑"이고, 4가지 Case 중 하나로 정합니다.

핵심. 4가지 Case는 결국 모두 "명령 0 → raw p0", "명령 4095 → raw p4095"라는 대응점으로 바뀝니다. Case 3만 "명령 2048 → raw pMid"라는 점이 하나 더 있습니다. Case마다 다른 것은 이 점들을 어떤 입력으로 계산하느냐뿐이고, 실제 동작할 때는 대응점 사이를 직선으로 보간합니다 (mrsToRaw()).
예시: Case 2, min 1000 → max 3000

2. 사전 설정

매핑 설정이 효과를 내려면 아래 순서가 지켜져야 합니다. 번호 순서가 실제 처리 순서입니다. 단계를 누르면 해당 단계로 이동합니다.

    부팅 시 모터에 써 넣는 레지스터 (init())

    3. 패킷과 단위

    설정값은 DATA1과 DATA_OP 두 패킷을 합쳐서 완성됩니다. DATA_OP의 8바이트는 2바이트씩 4칸으로 나뉘고, case_num에 따라 각 칸의 의미가 달라집니다.

    필드타입단위 / 변환사용 Case

    angleuint160.01° 단위. 9000 = 90.00°. 보드에서 angle / 100 후 float로 보관1, 4

    DATA_OP (prtc_data_ctl_init_driver_data_op_dxl2_t, 8바이트, 리틀엔디언)

    case_nummin (byte 2-3)ref_position (byte 4-5)max (byte 6-7)DATA1 angle / direction

    "—" 칸은 펌웨어가 읽지 않습니다. 0으로 채워 보내는 것을 권장합니다.

    각도 → 카운트 환산

    angleCnt = angle(°) / 360 × 4095 // 소수점 이하는 버림 (최대 1카운트 오차) 예) 90° → 1023.75 → 1023 카운트 180° → 2047.5 → 2047 카운트
    방향 표기 주의. 코드의 CW/CCW는 raw 카운트가 커지는 쪽 / 작아지는 쪽이라는 뜻입니다. 로보티즈 e-Manual에 따르면 Drive Mode가 일반 방향(현재 설정)일 때는 위치값이 커지면 모터 정면 기준 반시계 방향으로 돕니다. 실제 회전 방향은 장비에서 꼭 확인하세요. 이 문서의 그림은 XM430을 정면(혼 쪽)에서 본 모습이고, 일반 모드에 맞춰 raw가 커지면 반시계 방향으로 돌게 그렸습니다. 외형은 실측 28.5 × 46.5 mm 비율이지만 혼 위치와 구멍 배치는 개략이고, 0 위치는 12시로 가정했습니다.

    4. 설정 방법 4가지

    각 그림에서 왼쪽은 XM430을 혼 쪽(정면)에서 본 모습이고 raw 0~4095를 한 바퀴로 그렸습니다. 오른쪽은 명령값 → raw 그래프입니다. 명령값이 0 → 4095 → 0으로 반복해서 움직입니다. 청록색 띠가 실제 구동 범위입니다.

    CASE 1

    시작점 · 각도 매핑

    언제 쓰나. 동작을 시작할 위치(명령 0)를 엔코더값으로 알고 있고, 거기서 몇 도만큼, 어느 방향으로 움직일지 정할 때 씁니다.

    논리. ref_position에 명령 0을 고정합니다. 끝점(명령 4095)은 시작점에서 angle만큼 direction 방향으로 이동한 위치입니다.

    p0 = ref_position p4095 = p0 + dirSign × angleCnt (CW=+1, CCW=−1)

    예. ref 1000, 90°, CW → p0 = 1000, p4095 = 2023. 명령 2048 → raw 1511.

    범위 초과. ref 1000, 90°, CCW이면 끝점이 −23이 되어 0으로 잘립니다. 그러면 실제 구동각은 90°보다 작아집니다. 시뮬레이터의 "Case 1 범위초과" 프리셋으로 확인할 수 있습니다.
    ref 1000 · 90° · CW
    CASE 2

    양끝점 매핑

    언제 쓰나. 장비에서 양 끝 위치의 엔코더값을 직접 재서 쓸 때 씁니다. 가장 직관적이고 계산이 없습니다.

    논리. min이 명령 0, max가 명령 4095에 대응합니다. 그 사이는 직선으로 보간합니다. direction은 보지 않습니다. min > max이면 자동으로 역방향이 됩니다.

    p0 = min p4095 = max raw = p0 + (p4095 − p0) × cmd / 4095

    예. min 3000, max 1000 → 명령이 커질수록 raw가 줄어듭니다. 명령 2048 → raw 2000.

    min 3000 → max 1000 (역방향)
    CASE 3

    3점 분할 매핑

    언제 쓰나. 중앙 위치가 양끝의 정가운데가 아닐 때 씁니다. 예를 들어 링크 구조 때문에 앞쪽 구간과 뒤쪽 구간의 기울기가 달라야 하는 경우입니다.

    논리. 명령 2048을 경계로 두 직선 구간으로 나눕니다. 앞 구간은 min → ref, 뒤 구간은 ref → max입니다. direction은 보지 않습니다.

    cmd < 2048 : raw = min + (ref − min) × cmd / 2048 cmd ≥ 2048 : raw = ref + (max − ref) × (cmd − 2048) / 2047

    예. min 1000, ref 1500, max 3000 → 앞 구간은 2048스텝에 500카운트(완만), 뒤 구간은 2047스텝에 1500카운트(가파름).

    주의. 펌웨어는 ref가 min과 max 사이에 있는지 검사하지 않습니다. ref가 바깥에 있으면 명령이 한 방향으로 움직이는데도 모터는 갔다가 되돌아옵니다.
    1000 / 1500 / 3000
    CASE 4

    중앙점 · 대칭각 매핑

    언제 쓰나. 중립(가운데) 위치의 엔코더값을 알고 있고, 그 위치를 중심으로 좌우 같은 각도로 움직일 때 씁니다.

    논리. ref_position이 범위의 중앙입니다. 전체 각도의 절반씩 양쪽으로 펼치고, direction은 명령 0이 어느 쪽에 올지를 정합니다.

    half = trunc(angleCnt / 2) p0 = ref − dirSign × half p4095 = ref + dirSign × half

    예. ref 2048, 90°, CW → half 511, p0 = 1537, p4095 = 2559. 명령 2048 → raw 2048. 대칭 구조라 명령 중앙이 기계 중앙과 일치합니다.

    angle은 전체 각도입니다. 90°로 보내면 좌우 각각 45°입니다. 한쪽 각도가 아닙니다.
    ref 2048 · 90° · CW

    Case 고르기

    알고 있는 값권장 Casedirection
    시작 위치 + 구동각1필요
    양 끝 위치 (실측)2불필요 (min/max 순서가 방향)
    양 끝 + 중앙 위치 (비대칭)3불필요
    중립 위치 + 전체 구동각4필요

    6. 코드 규칙

    v0.0.8 코드에 정해진 동작 규칙입니다. 상위 개발이나 현장 세팅 때 이 규칙을 전제로 두면 됩니다. 표시 기준: 규칙 정해진 동작, 주의 실수하기 쉬운 점.

    스케일
    명령값은 항상 0~4095

    범위를 벗어난 명령(uint16이라 4095 초과가 들어올 수 있음)은 0 또는 4095로 고정한 뒤 변환합니다.

    MRS_CMD_MAX · mrsToRaw() · setPosition()
    클램프
    대응점은 raw 0~4095로 잘림

    p0 / pMid / p4095를 계산한 뒤 모터 물리 범위로 자릅니다. 대응점이 범위 안이면 보간 결과도 항상 범위 안입니다. 클램프가 동작했다면 설정값이 모터 사양을 벗어났다는 뜻이므로, 의도한 각도가 나오지 않습니다. 설정값을 다시 확인하세요.

    clampToPosiRange()
    단위
    angle은 0.01° 단위, 카운트 환산은 버림

    angle/100을 float로 보관하고, angle/360×4095를 정수로 바꿀 때 소수점을 버립니다 (반올림 아님, 최대 1카운트). Case 4는 그 값을 다시 2로 나누고 버립니다.

    dxl_task.cpp MRS_RX_DATA1 · setSettingData_op()
    방향
    direction 0 = CW(+), 그 외 = CCW(−). Case 2·3은 무시

    Case 2·3은 min과 max의 크기 순서로 방향이 정해집니다. CW/CCW는 raw 증감 방향을 뜻하는 이름입니다. 로보티즈 기준(정면, 일반 모드)으로는 코드의 CW(+)가 실제로는 반시계 회전입니다.

    DXL_ROT_CW / DXL_ROT_CCW
    분할점
    Case 3 경계는 2048 (앞 2048스텝, 뒤 2047스텝)

    정확한 중앙은 2047.5지만 상위와 2048로 합의했습니다. 그래서 1스텝 비대칭입니다.

    MRS_CMD_MID
    거부
    지원하지 않는 case_num은 반영하지 않고 0xFFFF로 응답

    1~4가 아니면 기존 설정을 유지합니다. DATA_OP_ACK의 case_num 자리에 0xFFFF를 싣고 나머지 6바이트는 0으로 보냅니다. 정상이면 받은 8바이트를 그대로 되돌려 주므로, 상위는 ACK를 보고 반영 여부를 검증할 수 있습니다.

    isSupportedCase() · DXL_MAP_CASE_REJECT
    재설정
    DATA_OP는 언제 받아도 항상 반영

    이전 상태와 상관없이 매핑을 덮어쓰고, Run 중인 모터도 Statis_SettingOk로 되돌립니다. 새 매핑으로 움직이려면 초기위치 이동(MOVE_DEFAULT_POSI)을 다시 거쳐야 합니다.

    setSettingData_op()
    순서
    DATA_OP를 받기 전에는 위치 명령과 조그가 무시됨

    매핑이 할당되어야(f_assign) 위치 명령을 받습니다. DATA1만 보내서는 움직이지 않습니다. 조그도 마찬가지입니다 (코드에 TODO로 재확인 표시가 있음).

    f_assign · setPosition() · setJogMove()
    초기위치
    init_position도 같은 매핑으로 변환

    DATA1의 init_position은 명령값입니다. 동작 중 명령과 같은 mrsToRaw()로 raw로 바꾸므로, Case 3의 구간 분할도 그대로 적용됩니다.

    getDefaultPosi()
    전송
    같은 raw는 다시 보내지 않음, 응답도 기다리지 않음

    변환한 raw가 직전 Goal Position과 같으면 버스에 쓰지 않습니다. 위치 쓰기는 응답 없이 전송(write4ByteTxOnly)합니다. Status Return Level이 1이기 때문입니다.

    setPosition()
    에러
    init()에서 reboot 금지

    reboot은 래치된 Hardware Error Status(주소 70)를 지워 버립니다. 그러면 에러를 영영 검출하지 못하므로 비활성화되어 있습니다. 다시 켜지 마세요.

    init() 주석 [사용 금지]
    재초기화
    DATA1을 다시 받아도 init()은 다시 실행하지 않음

    init()은 부팅 시 initializeAll()에서만 실행합니다. 모터가 InitError 상태이면 DATA1에 ACK 대신 "InitErr" 하드웨어 에러 이벤트를 보냅니다.

    dxl_task.cpp MRS_RX_DATA1
    버스
    모션 동작 중에는 Hardware Error를 주기적으로 읽지 않음

    Status_Run 중에는 버스 READ를 줄여서 HardFault를 막습니다. SCALE_RAW 요청에는 버스를 읽지 않고, 마지막 Goal Position raw 캐시(getRawCommandPosition())로 응답합니다.

    getRawCommandPosition() · 커밋 7233b32, c857bba
    에러 비트
    Hardware Error 응답의 bit6·bit7은 보드가 정의한 값

    bit6 = 3회 연속 통신 실패, bit7 = 매핑 미할당 모터입니다. bit0·2·3·4·5는 로보티즈 원본 에러 비트(전압, 과열, 엔코더, 전기충격, 과부하)입니다. 통신 실패가 1~2회일 때는 0(정상)으로 보고합니다.

    getHardwareErrorStatus() · DXL_Protocol.h
